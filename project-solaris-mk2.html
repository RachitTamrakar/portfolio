Solaris Mk II Hybrid Engine & Ground Station

Controls Lead • Monash High Powered Rocketry • August 2023 - June 2025

Python STM32 MQTT SCADA RS422/CAN Embedded Systems

Project Zenith rocket launching at IREC 2025, powered by Solaris Mk II

Overview

Achievement: Won Jim Furfaro Technical Excellence Award (out of 140+ teams) and 2nd place in category at IREC 2025

Led the design and development of ground station electronics for a 4 kN thrust N₂O/paraffin hybrid rocket engine that successfully flew to 12,000 feet at the 2025 Intercollegiate Rocket Engineering Competition.

The ground station provided complete control and monitoring for fueling, ignition, and data acquisition across 20+ sensor channels at 100 kHz, enabling safe and reliable engine operations throughout the test campaign and competition.

The Challenge

Building a reliable control system for a hybrid rocket engine presented several critical requirements:

  • Safety-Critical Operations: Control high-pressure N₂O fueling and high-voltage ignition systems with zero tolerance for failure
  • Real-Time Performance: Monitor 20+ sensors at 100 kHz and execute automated sequences with millisecond precision
  • Reliability Under Pressure: System must function flawlessly during time-constrained competition operations
  • Integration Complexity: Coordinate between LabJack DAQs, STM32 microcontrollers, and Raspberry Pi over multiple protocols

My Role & Contributions

Electrical Cabinet Design

Designed and constructed complete electrical cabinet for engine ground systems:

  • DIN rail mounted components: power supplies, networking hardware, Raspberry Pi, LabJack DAQ, motor drivers, relays
  • Fabricated custom cable assemblies and connectors for actuators, sensors, and communication lines
  • Applied structured electrical design principles learned from professional work at Bosch
  • Built for reliability under vibration and condensation conditions in field environment

Control Architecture

Developed distributed control system integrating multiple hardware platforms:

  • Communication: RS422, CAN bus, MQTT protocols for device coordination
  • Hardware Integration: LabJack DAQs (Ethernet), STM32 microcontrollers, Raspberry Pi main controller
  • Automated Sequences: Fill, ignition, and abort procedures with safety interlocks
  • Data Acquisition: 100 kHz sampling across 20+ sensor channels with real-time monitoring

Software Stack

Built complete software system from control logic to operator interface:

  • Multithreaded Python backend implementing state machines for fill, ignition, and abort
  • Ignition SCADA interface for real-time monitoring and telemetry visualization
  • MQTT-connected database for long-term data logging and analysis
  • High-rate local telemetry recording for detailed post-test diagnostics

Hardware Evolution

Designed and built three successive hardware iterations, each refined based on test results:

  • V1: Proof-of-concept with basic valve control and monitoring
  • V2: Added high-speed data acquisition and improved safety interlocks
  • V3: Final system capable of 100 kHz acquisition, fully integrated ignition control, and competition-ready reliability

Technical Decisions & Problem Solving

Crisis Management at IREC

When the propellant level sensor failed the night before launch, I stayed up debugging with the propulsion lead to identify the issue. By morning, we had successfully troubleshooted the system, leading to flawless operation and a successful launch that contributed to our award win.

Distributed Architecture

Initially considered a single microcontroller approach, but chose a distributed system to:

  • Separate safety-critical hardware control (STM32) from high-level sequencing (Raspberry Pi)
  • Leverage LabJack's high-speed DAQ capabilities without overwhelming the main controller
  • Enable parallel development of hardware control and operator interface
  • Provide redundancy and fault isolation for critical operations

Safety Interlocks

Implemented multiple layers of safety mechanisms:

  • Hardware interlocks preventing simultaneous valve operations
  • Software watchdogs monitoring system health
  • Redundant control paths for high-consequence operations
  • Emergency abort capability with physical and software triggers
