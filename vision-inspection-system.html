Multi-Station Vision Inspection System

Unified C# application controlling 40+ cameras across 6 inspection stations on an $8M production line

Bosch Australia Manufacturing Solutions • 2024-2025
C# .NET WPF HALCON SQL Server ProfiNet Computer Vision Multithreading
⚠️ Confidentiality Notice: Due to confidentiality, photos and videos cannot be shared. Any photos shown are of similar systems.

The Challenge

Developed for an $8M biodegradable packaging production line with no internal templates or departmental precedent to reference. Customer required 100% inline inspection—no sampling—meaning any false negatives directly impact product quality. I had to architect the system from scratch while learning C# in real-time.

Scale & Performance

40+ cameras across 6 inspection stations operating at ~0.6 second cycle time required a highly optimized multithreaded architecture.

Real-Time Quality

Customer required real-time quality validation across the entire production line with immediate feedback to operators.

Learning Curve

Had to learn C# from scratch while simultaneously building a production-critical system with no departmental precedent.

Technical Implementation

System Architecture

Built a single unified C# application using a multithreaded WPF architecture that manages all 6 inspection stations from one codebase. Each station runs 4-12 cameras with independent inspection pipelines.

Camera System

Integrated 40+ cameras using HALCON vision library with asynchronous pipeline design for sub-second cycle times. Each camera operates independently with automatic reconnect logic to handle failures gracefully.

PLC Integration

Designed handshake logic for ProfiNet communication with Siemens PLCs. I wrote a custom C# wrapper for the Hilscher cifX fieldbus card, sketching handshake sequences in flowcharts before coding and collaborating with automation engineers to refine protocols.

Data Management

Implemented SQL Server Express logging for product traceability across all stations. This feature was added mid-project per customer request, requiring careful integration into the existing pipeline.

Configuration System

Used config files to manage per-station differences from a single codebase, enabling one application to control all stations while accommodating unique camera counts and inspection requirements.

Result: Met sub-second cycle time requirements. Architecture became the department's blueprint for future vision systems.

Development Process

I built the system incrementally, starting with a dummy test harness, then adding camera interfaces, the logging system, and finally PLC integration. This methodical approach allowed me to validate each component before adding complexity.

1

2

3

Result: Incremental validation enabled zero production downtime during deployment. Each layer tested independently before integration.

Technical Challenges Overcome

Multithreading Race Conditions

Early design had race conditions that required a complete architecture redesign. I abandoned the initial GUI/inspection app split in favor of a unified interface that gave operators real-time adjustability.

Cycle Time Requirements

Refactored major code sections on two stations to meet strict ~0.6 second cycle time requirements. Optimized image processing pipelines and reduced synchronization overhead.

Network Configuration

Managed NICs, DHCP settings, and resolved packet collisions and dropped frames. Optimized network topology to handle high-bandwidth camera feeds without interference.

Mid-Project Feature Addition

Customer requested SQL logging capability mid-project. Successfully integrated database layer without disrupting existing inspection pipeline or cycle time.
